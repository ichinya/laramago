The compatibility rule restores one model attribute read after a repeated native refresh. It selects the complete native `no-value` Error for the first argument of `Testo\Assert::same`, the entire property expression, a current physical caller, and two unconditional refreshes on the same local receiver. The earlier assertion must name the same field with a different literal.

The existing model refresh contracts independently verify the native refresh and assertion implementations, closed receiver lifetime, primitive reads, accessor and cast precedence, migration column domain, class descendants, and source hashes. A separate field contract binds every owner field read by the private typed producer helper to its physical PHP declaration and genuine SDK property, including its declared and effective object types. These fields must belong to classes unrelated to the returned model; a nested model field read keeps the audited primitive reader contract.

An explicitly fresh or known unsaved model, an alias or reference, a receiver write, a conditional refresh, a changed native reader, a constant accessor, an inadmissible expected literal, source termination, or a declared local `never` call keeps the diagnostic. The rule does not execute the application or database and does not change native types.

It compares native and AlwaysKeep reports, isolated one/three-worker reports, and full production registration before/after one/three-worker reports. Every other complete diagnostic must remain identical. Actual populated SDK cache entries are changed only after a genuine positive, immediately after the selected native contract is re-queried, and restored after every control. The controls run with one analyzer thread; production retains the default engine setting.

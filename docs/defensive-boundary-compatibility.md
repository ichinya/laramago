# Defensive boundary compatibility

The Laravel preset keeps defensive checks at external and mutable boundaries useful to the application while matching PHPStan's reporting conventions. These policies change selected advisory reporting and preserve native value types, method signatures, deprecation flags and unrelated diagnostics.

Configuration classification checks qualify when the selected branch only validates a dependent field from the same certified configuration record. A business branch, unknown producer, reassignment or changed framework helper remains outside the policy. Native printed array shapes support quoted identifier keys containing `/` or `*`, as used in route patterns; escaped keys and incomplete native type fragments remain unsupported.

Captured-state checks qualify through a closed source pattern for by-reference counters, written values or a recursive visited set. Stored callbacks require a current physical nullable `Closure` field. Its own bounded PHPDoc signature can provide a more precise callable contract when current native metadata matches that declaration. The policy reflects PHPStan's treatment of defensive mutable-state checks; it does not assert that a stored callback executes or that an external producer is pure.

Response checks qualify for the physical Inertia page producer, its current page properties and the standard page-to-props validation sequence. The source and native factory, wrapper, macro and override checks used for the page return contract also apply to these advisories.

`CapturedStateGuardPlugin` and `DefensiveResponseGuardPlugin` accept an optional `preserveAdvisories` constructor argument. Passing `true` retains their native warnings. The default is `false`.

# Captured method guards

A captured `$this` arrow can retain the fact established by a surrounding `method_exists($this, 'method')` check. The selected registration must store the callback through a current physical append-only declaration. A local registration receiver can be bound through a dominating class guard and a matching physical method return declaration. Reassignment, unknown aliasing, a reference capture or a callback transport that rebinds the closure prevents admission.

Earlier calls to an otherwise missing method that has its own `method_exists` guard use PHPStan's `HasMethodType` effects convention. This is a static analysis contract for the guarded method fact.

# Installed package defaults

Literal `app()` and `resolve()` calls can use the installed Fortify package's declared default binding for its two-factor authentication provider. The package must be present and enabled by standard Composer package discovery. The current helper, framework discovery implementation, package registration, contract and concrete class must match their bounded source and native profiles.

Configured binding files take precedence. A missing or unknown configured catalog, disabled discovery, changed registration or incomplete concrete class keeps the native helper result. This models the declared installed-package default; it is not a guarantee about every effective container binding after arbitrary application execution.

The concrete provider signature becomes authoritative after admission. A valid optional length argument is accepted, while a bad argument type or excess concrete arguments still produce their native errors.

# Deprecated methods

The default deprecation reporting policy preserves current native deprecation flags and method types. A physical `array` caller uses the native `array-key` domain, which includes integer and string keys. The builtin ReflectionMethod profile remains bound to its PHP version and current native API metadata.
